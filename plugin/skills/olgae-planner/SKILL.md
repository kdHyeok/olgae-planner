# PRD & 기능명세서 작업 규칙

`olgae-planner` MCP 툴로 이 서비스의 PRD 와 기능명세서를 다룰 때의 규칙이다.

## 데이터 구조

프로젝트 하나에 세 가지가 들어 있다.

1. **기능명세서 트리** — 최대 4단계(대분류 > 중분류 > 소분류 > 세부). `get_spec` 이 화면과 같은
   **계층 번호**(`1`, `1.1`, `1.1.1`)를 붙여 준다. 사용자와 대화할 때는 항목 id 가 아니라
   **이 번호와 제목으로 지칭**한다.
   - `status`: 기획 작성중 / 기획 완료 / 개발 중 / 완료
   - `importance`: 1 필수(Must) · 2 권장(Should) · 3 선택(Could) · 4 보류(Won't)
2. **표(컬렉션)** — PRD 는 표의 모음이다. `prd` 표는 섹션 문서(제목 + 마크다운 본문)이고,
   그 밖에 `policies`(핵심 정책) · `nfr`(비기능 요구사항) · `decisions`(미결정) ·
   `tests`(테스트 시나리오) 같은 표가 **프로젝트마다 있을 수도 없을 수도 있다.**
   `list_collections` 로 무엇이 있는지 먼저 확인한다.
   속성 타입: `text`(한 줄) · `md`(마크다운) · `select`(options 중 하나) · `checkbox` ·
   `relation`(다른 항목 번호의 배열).
3. **작업(`tasks` 표)** — `title` · `status`(할일/진행중/완료) · `kind`(에픽/작업/이슈) ·
   `parent`(상위 작업) · `related`(관련 기능·정책) · `body`.

### 번호와 링크

기능·표의 행·작업은 **프로젝트 안에서 하나의 번호(seq)를 공유**한다. 표기는 `<프로젝트키>-<번호>`(예 `PLNT-14`).

- 본문 아무 데나 `[[PLNT-14]]` 라고 쓰면 화면에서 **링크 칩**이 되고, 가리켜진 쪽에는
  "이걸 가리키는 항목"으로 자동 표시된다. 추적표도 이 링크에서 만들어진다.
- 앞의 키는 표시용이라 **번호만 맞으면 해석된다.** 키가 바뀌어도 링크는 깨지지 않는다.
- 구조적 연결이 필요하면 `relation` 속성에 번호 배열을 넣는다(예: 테스트의 `related`).
- **정책·요구사항을 근거로 기능을 만들거나 고칠 때는 그 기능 설명에 `[[번호]]` 로 근거를 남긴다.**
  이게 이 서비스를 쓰는 이유다 — 나중에 "왜 이 기능이 있나"를 추적할 수 있다.

## 시작 순서

1. `list_projects` 로 대상 프로젝트를 정한다. 여러 개면 사용자에게 확인받는다.
2. `get_spec` 으로 PRD 본문과 트리를 **먼저 통째로 읽는다.** 부분만 보고 고치지 않는다.
3. `list_collections` 로 어떤 표가 있는지 본다. 정책·요구사항이 있으면 `search_items` 로 훑는다.
4. 용어가 나오면 `list_terms` 로 정의를 확인한다.

## 작업 지시를 받았을 때

작업판(`tasks` 표)이 있으면 **작업을 만들거나 갱신하면서 진행한다.** 무엇을 했는지가 남아야 한다.

1. `search_items(collection='tasks', query='<핵심어>')` 로 **같은 작업이 이미 있는지 먼저 찾는다.**
2. 있으면 `update_item` 으로 `status` 를 `진행중` 으로 옮기고, 알게 된 내용을 `body` 에 덧붙인다.
   없으면 `create_item` 으로 만든다(`title` · `status: 할일` · `kind`).
3. 관련 기능·정책이 있으면 `related` 에 번호를 넣거나 `body` 에 `[[번호]]` 로 적는다.
4. 끝나면 `status` 를 `완료` 로 옮긴다. 중간에 막히면 완료로 옮기지 말고 `body` 에 막힌 지점을 적는다.
5. 큰 단위라면 `kind: 에픽` 으로 하나 만들고, 쪼갠 작업들의 `parent` 에 그 번호를 넣는다.

바뀐 값은 이력으로 남아 사용자가 누가 언제 무엇을 바꿨는지 화면에서 본다. 상태를 함부로 되돌리지 않는다.

## 작성 컨벤션

### 백틱은 용어 사전 전용이다

본문에서 `` `단어` `` 처럼 백틱으로 감싼 텍스트는 **용어 사전에 자동 등록되고 화면에서 용어 링크로 표시**된다.

- 처음 정의하거나 반복해 쓰는 도메인 용어에만 쓴다.
- **코드 조각·파일명·명령어·필드명을 백틱으로 감싸지 않는다.** 용어 사전이 오염된다.
  코드나 값은 따옴표(예: "status") 또는 그냥 평문으로 쓴다.
- 용어는 본문에서 자동 수집되므로 사전에서 직접 만들 수 없다. 새 용어를 넣으려면 본문에 백틱으로 쓴다.
- **주의**: 어떤 용어의 마지막 사용처를 본문에서 지우면 그 용어 행과 **작성해 둔 설명까지 사라진다.**
  용어를 걷어낼 때는 사용자에게 먼저 알린다.

### 링크와 이미지

- 링크: `[표시이름](https://...)`. 주소만 적어도 자동 링크가 된다.
- 이미지: `![](/api/images/<id>)`. 업로드는 웹 UI(붙여넣기·끌어놓기)에서 한다.
- 지원 문법: 제목 `#`~`###`, 불릿 `- `, 표(`| 머리 | 글 |` + `|---|---|`), 강조 `**굵게**` · `*기울임*`.

### 본문에 붙어 있는 URL 은 열어서 확인한다

PRD 나 기능 설명에 링크가 있으면 **내용을 실제로 열어 읽고** 판단한다.
링크 제목이나 주소만 보고 내용을 추측해 요약하거나 근거로 쓰지 않는다.
열 수 없으면(접근 불가·로그인 필요) 그 사실을 밝히고 사용자에게 묻는다.

## 산출물 원칙 — 명세에 있는 것만 쓴다

와이어프레임·유저플로우·화면 목록·API 초안·테스트 케이스 등 **명세를 근거로 만드는 모든 산출물**에 적용한다.

- 명세에 **없는 화면·필드·상태·분기·역할을 만들어 넣지 않는다.** 그럴듯한 보완도 창작이다.
- 산출물의 각 요소에는 근거가 된 **항목 번호를 표기**한다(예: "로그인 화면 — 1.2 로그인").
- 명세가 부족해 산출물을 완성할 수 없으면, 빈칸을 메우지 말고 다음 중 하나를 한다.
  1. 부족한 지점을 **목록으로 정리해 사용자에게 질문**한다.
  2. 사용자가 동의하면 **명세에 항목을 먼저 추가**하고(`create_node` / `update_node`) 그것을 근거로 산출물을 만든다.
- 설명이 비어 있는 용어의 뜻을 **추측하지 않는다.** 사전에서 확인하고, 없으면 물어본다.
- 명세와 어긋나는 점을 발견하면 조용히 고치지 말고 짚어서 알린다.

## 안전 규칙

- 트리나 표를 **여러 항목 고치거나 지우기 전에는 `save_version`** 으로 스냅샷을 먼저 남긴다.
  버전은 PRD 섹션·모든 표·기능 트리를 함께 담고, 복원해도 번호가 유지되어 링크가 깨지지 않는다.
- `create_item` / `update_item` 의 `props` key 는 **`list_collections` 로 확인한 속성 key** 를 쓴다.
  스키마에 없는 key 는 조용히 무시되고, `select` 는 options 밖의 값을 거부한다.
- 표나 속성을 지우는 툴은 없다. 사용자가 화면에서 한다(속성을 지우면 모든 행의 값이 사라지기 때문).
- `delete_node` 는 **하위 항목과 코멘트까지 함께** 지우고 되돌릴 수 없다. 사용자 확인 없이 호출하지 않는다.
- `restore_version` 은 그 시점 이후의 변경을 되돌린다. 반드시 사용자 확인을 받는다.
- `set_prd` 는 **본문 전체를 덮어쓴다.** `get_spec` 으로 받은 원문을 고쳐서 통째로 보낸다.
- `add_comment` 의 작성자는 연결된 토큰의 주인으로 기록된다. 사용자를 대신해 쓰는 것이므로 남길 내용을 알린 뒤 쓴다.
- 툴이 403/404 를 돌려주면 권한이나 대상 문제다. 다른 프로젝트로 우회 시도하지 않고 사용자에게 알린다.

## 하지 말 것

- 명세에 없는 내용을 채워 넣기
- 코드·파일명을 백틱으로 감싸 용어 사전을 오염시키기
- 첨부 링크를 열지 않고 내용을 단정하기
- 사용자 확인 없이 항목 삭제·버전 복원
- 항목 id 만으로 사용자와 대화하기(계층 번호와 제목을 쓴다)
- 정책·요구사항을 근거로 기능을 고쳤는데 `[[번호]]` 를 남기지 않기
- 작업판이 있는데 작업을 만들지 않고 진행하기
- 끝나지 않은 작업을 `완료` 로 옮기기
